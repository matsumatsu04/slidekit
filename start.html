SlideKit 導入手順

SlideKitは、スライドの「デザイン」と「構図」を型として固定し、Claude Codeとの会話だけで 統一感のあるスライド（HTML＋PDF）を生成する仕組みです。下のセットアップ用の文章をClaude Codeに貼り付けるだけで導入できます（3〜5分）。

準備するもの

  • Claude Code のデスクトップアプリ（Mac / Windows）。Windowsでは初回起動時に Git for Windows の導入を求められます
  • Node.js（バージョン18以上。ビルド・一覧の更新・チェックのツールが使います。node -v で確認）
  • git（macOSは最初から入っていることが多く、WindowsはGit for Windowsで入ります。無ければ導入までClaude Codeが案内します）
  • Google Chrome（PDF書き出しに使用。ブラウザ印刷でも代替できます）

導入（Claude Codeに貼るだけ）

下のボタンでプロンプトをコピーし、Claude Codeのデスクトップアプリに貼り付けてEnterを押してください。 取得・環境チェック・動作確認までをClaude Codeがやってくれます。所要3〜5分。

このときの作業フォルダはどこでもかまいません（アプリの「Select folder」で選んでいるフォルダ）。 導入先は自動で ~/slidekit になります。

クリックしてコピー → Claude Codeに貼り付け 
SlideKit（スライド自動生成の仕組み）をこのPCで使えるようにセットアップしてください。
下の手順どおりに実行し、最後に日本語で結果を報告してください。

1. 取得する（置き場所は ~/slidekit）
   if [ -d ~/slidekit/.git ]; then git -C ~/slidekit pull --ff-only; else git clone https://github.com/matsumatsu04/slidekit.git ~/slidekit; fi

2. 環境チェック
   cd ~/slidekit && bash tools/doctor.sh
   - ✗ が出たら解消する。Node.js 18以上が必須。すでに新しいNode.jsが別の場所にある場合は doctor が場所を教えるので、表示された export PATH=... を使う。
     どこにも無い場合はインストール方法を提案し、許可を得てから実行する（macOSはHomebrewがあれば brew install node、Windowsやそれ以外は https://nodejs.org/ja のLTS版）。
   - △（Chrome / poppler）は無くてよい。無理に入れない（PDFはブラウザの「PDFに保存」でも作れる）。
   - 解消したら doctor をもう一度実行し「✓ 準備OK」を確認する。

3. 古いコピーの後片付け（該当する人だけ）
   ls ~/.claude/skills 2>/dev/null | grep '^slidekit-'
   表示された場合のみ rm -rf ~/.claude/skills/slidekit-* を実行する。
   （スキルは ~/slidekit/.claude/skills/ に入っているのでコピーは不要。
     ~/.claude/skills/ 側は全フォルダ共通で、同名なら常にそちらが優先されるため、古いコピーが残っていると更新が反映されない）

4. 自分用の素材フォルダを決める（ロゴなどをスライドに使えるようにする）
   まず利用者に日本語でこう聞く（勝手に決めない）:
   「ロゴや写真など、自分の素材をスライドに使えるようにします。素材を置くフォルダを決めてください。
     指定が無ければ ~/slidekit-assets を作ります（あとで変更できます）。
     Googleドライブなど同期フォルダの中を指定してもかまいません」
   返事を受けてから次を実行する:
   - フォルダが無ければ作る（例: mkdir -p ~/slidekit-assets）
   - 場所を登録する（~/slidekit-assets 以外を選んだ場合は必ず実行する）:
     mkdir -p ~/.slidekit && printf '{"assetsDir":"%s"}\n' "<選ばれたフォルダの絶対パス>" > ~/.slidekit/config.json
   - 使い方を伝える: そのフォルダに置いた logo.png は、スライドを作るときに assets/logo.png で呼び出せる。
     サブフォルダを作った場合は assets/<サブフォルダ>/<ファイル名> で呼び出せる。

5. 動作確認（サンプルを1本ビルドする）
   cd ~/slidekit && rm -rf output/setup-check && mkdir -p output && cp -R examples/html-deck-demo output/setup-check && node tools/html-deck/build-html-deck.mjs output/setup-check && bash tools/html-deck/export-pdf.sh output/setup-check
   - index.html と deck.pdf ができれば成功。QA画像（qa-*.jpg）は無くてもよい。
   - node が古いと言われたら、手順2で案内された新しいNode.jsのパスで同じコマンドを実行する。
   - 確認できたら rm -rf ~/slidekit/output/setup-check で片付ける。

6. 報告する（日本語で、次を必ず含める）
   1) 導入先のパス／使えるようになった構図パターンの数／Node.jsのバージョン／素材フォルダの場所
   2) 次にやること（デスクトップアプリの操作として書く）:
      「画面下の『Select folder』から ~/slidekit フォルダを選び直して、『スライドを作って』と話しかける」
      ※スライド生成のスキルは ~/slidekit を作業フォルダに選んでいるときだけ使えます。
        別のフォルダを選んでいると反応しません（新しいセッションを開いて選び直せば切り替わります）
   3) できること3つとURL:
      - スライドを作る … 作業フォルダを ~/slidekit にして「スライドを作って」。出来上がりは ~/slidekit/output/ に入る
      - 直す・PDFにする … https://slide.macminol.com/deck.html
      - 構図を探す … https://slide.macminol.com/
   4) 覚えておくとよいこと:
      - 新しい構図パターンや機能は自動で追加される。「スライドを作って」と言うと最初に更新確認が入るので、聞かれたら「はい」と答える
      - ~/slidekit の中のファイルは編集しない（更新を受け取れなくなる）。作ったスライドは output/ に入る
      - 自分の素材フォルダに置いた画像は assets/<ファイル名> で呼び出せる（「表紙にうちのロゴを入れて」と頼めばよい）
      - スライドに淡い背景画像を敷ける。表紙など不要なページは1枚単位でオフにできる

注意
- システムに変更を加える操作（Node.jsの導入など）は、実行前に必ず何をするか説明して許可を取ること。
- 手順が失敗したら、勝手に別の方法を試さず、失敗した内容と対処案を報告すること。
Node.jsの導入など、PCに変更を加える操作は実行前に確認を求められます。内容を読んでから許可してください。

できたスライドの確認・修正・PDF保存

  1. 生成された index.html を スライド確認 のページにドラッグ＆ドロップ
    （Claude Codeが表示したファイルパスの貼り付けでも開けます。初回だけフォルダの許可が要ります・Chrome/Edge対応）
  2. スライドが一覧表示されるので、直したいスライドの下の欄に修正指示を書く（構図を変えたい場合はギャラリーで探したパターンID（P045等）を記入）
  3. 「修正プロンプトを出力」を押してコピーし、そのままClaude Codeに貼り付けると修正版が生成される
  4. 仕上がったら「PDFとして保存（印刷）」からPDF化（印刷ダイアログで「PDFに保存」を選択）
  5. そのまま発表するときは「▶ 発表」でスライドをウィンドウいっぱいに表示（→キーやクリックで送り・Escで終了。タブ・URLバーは残るので、発表中に他のタブへ切り替えて見せることもできます）
カラーパレット（配色セット）はギャラリー・確認ページのどちらでも試着できます。 気に入った配色があれば、修正プロンプトに自動で含まれるので、そのままClaude Codeに渡せば反映されます。

自分のロゴ・画像を使う

導入時に決めた自分用の素材フォルダ（既定は ~/slidekit-assets）に画像を置くと、そのままスライドで使えます。 このフォルダは自分で管理する場所なので、ローカルでも、Googleドライブなどの同期フォルダの中でもかまいません。

  1. フォルダに画像を置く（例: logo.png、写真/オフィス.jpg）
  2. Claude Codeに「表紙にうちのロゴを入れて」のように頼む（スライド側では assets/logo.png として参照されます）
置き場所を変えたいときは ~/.slidekit/config.json の assetsDir を書き換えます （{"assetsDir":"/Users/自分/Google ドライブ/slidekit-assets"} のような形）。Claude Codeに「素材フォルダを○○に変えて」と頼んでも直してくれます。
置いた画像は書き出したHTMLに埋め込まれるので、スライドを人に渡しても画像は表示されます（フォルダごと渡す必要はありません）。

更新（新しいパターンを受け取る）

パターンは随時増えます。slidekit フォルダで次を実行するだけです。

git pull

自分で実行しなくても、「スライドを作って」と言った最初にClaude Codeが更新の有無を確認し、 新しいパターンがあれば「更新しますか？」と聞いてくれます（「はい」で反映）。

うまくいかないとき

まず環境チェックを流すと、原因と直し方がそのまま表示されます。

cd ~/slidekit && bash tools/doctor.sh
  • 「スライドを作って」に反応しない → 作業フォルダが ~/slidekit になっているか確認（アプリ下部の「Select folder」で選び直すか、新しいセッションを開いて選択）。別のフォルダを選んでいるとスキルが読み込まれません
  • 以前 ~/.claude/skills/ にコピーしたことがある → ~/.claude/skills/ は全フォルダ共通で、同名なら常にそちらが優先されます。古いコピーが動いてしまうので rm -rf ~/.claude/skills/slidekit-* で削除してください
  • 自分のロゴ・画像がスライドに出ない → 素材フォルダの場所が登録されているか確認（cat ~/.slidekit/config.json）。既定は ~/slidekit-assets です。フォルダに置いた logo.png は assets/logo.png で呼び出します
  • ビルドでNode.jsのエラーが出る（ERR_REQUIRE_ESM 等） → node -v が18以上か確認。古い場合は最新のLTS版を導入（Claude Codeに「Nodeを更新して」と頼んでもOK）。tools/doctor.sh がPC内の新しいNode.jsを探して場所を教えます
  • PDFがうまく書き出せない → index.html をChromeで開いて ⌘P（Windowsは Ctrl+P）→「PDFに保存」でも同じものが得られます。Chromeが別の場所にある場合は CHROME_BIN="/パス/chrome" bash tools/html-deck/export-pdf.sh <フォルダ> で指定できます
  • 確認用画像（qa-*.jpg）ができない → poppler が未導入なだけで、PDFとHTMLは完成しています（brew install poppler で入れれば出ます）
